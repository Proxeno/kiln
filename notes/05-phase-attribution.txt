# Conclusions so far
1. The Amdahl "serial ~3.9ms" is NOT serial code: outside-parallel work is ~0.2 ms/frame
   (beginFrame+nalGather+padRotate+forkJoin). It is slice load imbalance: wall == max slice.
   Balanced bound at default s=4 = sliceSum/4 + 0.2 = ~11.3 ms (vs 16.6 measured).
2. ME dominates all work: default s=4 Phase2 ME = ~35.8 ms/frame thread-time = ~80% of sliceSum.
   Non-vectorised residual/recon/CAVLC is small (<10% of work). Deblock ~1-2.7 ms sum.
3. Slicing multiplies work: s1 total work 30.3 ms vs s4 sliceSum 44.6 ms (+47%), s8 (fast) +37% vs s4.
4. Managed allocation is a non-issue now: 7-9 KiB/frame, zero collections in 300 frames.
5. Atlas: not a structural cost or win at s=4.
