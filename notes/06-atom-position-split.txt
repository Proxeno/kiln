# SATD atom split by position type (1080p default s=4, n=60, KILN probe `satd`)
# Instrumentation added: unifiedIntegerAtomComputes, fracSatdAtomComputes,
# fracIntegerSatdAtomComputes, fracSadBlocks, fracQpelInterpolations.

Per frame:
  integer-pel transform-domain atoms   495.9K   (the previously reported "~500K")
    - unified sub-partition ring loop  377.0K   (76% of integer atoms; NO per-candidate SATD early exit)
    - hex 16x16 path                   118.9K
  fractional-pel atoms (RefineFrac)    411.9K   <- previously UNCOUNTED; ~45% of all SATD atoms
    - of which at integer (fx=fy=0)      1.2K
  frac SAD blocks                       41.8K
  qpel block interpolations             20.3K   (6-tap InterpolateLuma per whole block)

TOTAL SATD atoms/frame ~= 908K, not 500K. Split ~55% integer / ~45% fractional.

Cache facts re-established:
  - "candidate cache 8%" = the per-hex-search 256-slot stackalloc (dx,dy) memo in
    ScoreInterIntegerPelCached. It costs ~4KB of stack, NOT 169MB. 8% is expected:
    hex+diamond revisits ~8% of probes. Not a defect, not related to the atlas.
  - The 169MB structure is H264ReferenceTransformAtlas (2 DPB slots x ~78MB), hit rate 77%,
    integer-pel only. It can never serve the 412K fractional atoms (qpel blocks are
    interpolated, transient, keyed by nothing atlas-addressable).
  - Existing per-partition early exit: 78.6% of hex-path compositions bail early.
    The unified loop (76% of integer atoms) has no SATD-level bail; only an 8x8-SAD
    lower-bound pre-filter that always computes TL SAD and the rest lazily.

Implication: the atlas 8%-hit story was a conflation. Real targets, in order of atom mass:
  1) unified loop 377K atoms: add quadrant-level SAD-lower-bound gating (exact)
  2) RefineFrac 412K atoms: tighten/skip refinement (mostly approximate)
  3) atlas: integer-only, perf-neutral at s=4 (18.69 vs 18.66) -> candidate for removal

# Optimisation 1 (landed): quadrant-level SAD-lower-bound gate in unified sub-partition loop
# Skip a quadrant's 4 SATD atoms when every shape using it has lb=((sad+1)>>1)+mvCost STRICTLY
# above that shape's best score (strict '>' cannot affect tie-breaks -> bitstream-identical).
# Kill switch: H264PInterDiagnostics.DisableUnifiedQuadrantGate; probe mode `qgate`.
  byte-identity: 64-frame 1080p dump default vs qgateOff -> cmp identical (382831 bytes both)
  atoms: unified 377.0K -> 258.7K/frame (-31%); total integer 495.9K -> 377.7K (-24%)
  wall (interleaved, median, two runs):
    default-s4(gate on)  15.08 / 14.75   qgateOff-s4  17.02 / 16.32   -> ~10-11% frame-time win
    atlasOff-s4          14.86 / 14.72   qgateOff+atlasOff 16.30 / 16.29
  NOTE: with the gate on, atlasOff is now measurably EQUAL-or-FASTER than atlas at s=4.
  tests: 2207 green.

# Optimisation 2 (landed): dead second fractional-refinement round eliminated
# RefineFrac candidates are (fx,fy) in [0,3]^2 around one integer pel; mv>>2 is invariant, so
# round 2's origin always equals round 1's -> identical candidate set, deterministic, strict
# pruning -> provably no-op. Break when a round's origin repeats.
  byte-identity: 64-frame dump still cmp-identical to the pre-change stream
  atoms: frac SATD 411.9K -> 205.9K/frame (-50%); frac SAD blocks 41.8K -> 21.6K
  qpel interpolations ~unchanged (block cache already spanned rounds)
  wall (qgate probe): default-s4 15.08/14.75 -> 13.73 ms/frame; cumulative vs pre-gate 17.0 -> 13.7 (-19%)
  atlasOff-s4 13.73 == default-s4 13.73 (atlas now exactly neutral at s=4 with both changes)
  tests: 2207 green.

# Optimisation 3 (landed): H264ReferenceTransformAtlas DELETED
# Rationale (measured, post gate+round-dedup):
#   - integer-only by design; cannot serve the ~45% of atoms at fractional positions
#   - dump default vs atlasOff byte-identical (transform-domain SATD exact by Hadamard linearity)
#   - s=4: neutral (14.40/14.68 then 14.12/13.51 -- inside noise)
#   - s=1: atlasOff consistently FASTER: 26.72/26.07 (atlas) vs 25.68/24.73 (off)
#   - cost: ~169 MB at 1080p (2 DPB slots x (1952x1144) x 36 B), ~610 MB at 4K
# The per-MB rented refTransformCache grid stays and now serves the unified loop's
# transform-domain SATD; the hex 16x16 path scores from pixels with SAD-LB + bounded SATD
# (exactly the measured atlasOff configuration). Post-removal: byte-identical stream,
# 2207 tests green, default-s4 13.49 ms / default-s1 26.03 ms.

# Negative result: SAD-ordered fractional refinement (tried, reverted)
# Two-pass RefineFrac (gather qpel SADs, apply bounded SATD in ascending-SAD order) is
# provably bitstream-identical (verified byte-identical) but saved NOTHING:
#   fracSatdAtomComputes 12,356,473 -> 12,355,555 (-0.007%), wall unchanged.
# The seed's integer-search score already provides a tight stopAfter before any frac
# candidate is scored, so evaluation order is irrelevant; the surviving atoms are
# bounded-SATD partials that bail the same way in any order. Reverted.
